**Deployment:** managed by Hop3.

## Context

ADR 006 (`notes/adrs/006-front-end.md`, still status *Draft/Proposed*) set the direction: Flask-Vite + Tailwind + Alpine in, jQuery + flask-assets + Closure out. `docs/roadmap.md` carries it as release 1.2's "UI Modernization" item — still unchecked, under a header that still says "Q4 2024".

The `tailwind` branch did the visual conversion and then stalled. The last real migration commit is `5d64c05`, **2026-01-06**; everything since is chores and merges. It is 41 commits ahead of `devel` and 6 behind, and drifts further every week. Twenty of its 41 commit subjects say `wip:`; one says `refact: tailwind migration (currently broken)`.

Deployment moving to **Hop3** removes the old constraint — operators hand-running `npm install` and `flask assets build` per `docs/installation.md`, with an nginx rewrite for the webassets `/static/min/...` path. Deleting the LESS/Closure pipeline becomes a decision about our own build rather than about breaking installs.

**Outcome:** `tailwind` merges to `devel` and ships as 1.2 — templates native Tailwind, Bootstrap shim gone, LESS/Closure/flask-assets deleted, our own JS free of jQuery, ADR 006 *Accepted*.

**Out of scope this cycle:** jQuery itself and the vendored plugins backing real features (DataTables, select2, typeahead, FileAPI, tagsinput, bootbox). We rewrite *our* glue only and leave a written per-plugin exit assessment for the next cycle.

## Where the branch actually stands

The January notes (`local-notes/migration-to-tailwind-plan.md`, `template-migration-inventory.md`) report ~72% complete and treat the JS migration as done. **They are wrong in a way that matters: the JS asset layer was removed before a replacement existed.** On `tailwind` today:

- **No icons.** FontAwesome CSS is never shipped, and the branch *raised* `fa fa-` usage to 139 occurrences across 34 templates by changing `action.py`'s `Glyphicon` to emit `<i class="fa fa-…">`. Every icon is a blank box.
- **No DataTables, no Select2, no rich-text / file / image / tags widgets.** Dropped from the bundle without replacement — while `datatables-setup.js` is still loaded and will throw on `$.fn.dataTable`.
- **The documents module is dead.** `sbe/extension.py` stopped registering the SBE JS and `abilian_base.html` comments the scripts out, but `documents/_macros.html` still calls `email_send_document()`, `edit_folder()`, `move_document()`, `delete_folder()`. A hand-written AMD shim resolves the missing module to `function(){}` — a silent no-op. Folder listing, selection, bulk delete, gallery, upload and viewer are all dead.
- **A fresh clone renders unstyled.** `vite/dist` is gitignored, nothing commits the build output, and no Makefile/CI/packaging step produces it.
- **The production asset URL is wrong.** The helper emits `/static/vite/…`; `copy-assets` writes to `src/abilian/sbe/static/vite/`, served at `/static/abilian/sbe/vite/`. Production Vite serving was never exercised — the SlapOS wrapper sets `FLASK_DEBUG=1`.

Both "done" markers are misnamed:

- `vite/src/components/bootstrap-compat.css` — **968 lines**, 37% of all new CSS, re-implementing ~180 Bootstrap class names via `@apply`.
- `vite/src/alpine-components.js` — **contains no Alpine.** 297 lines of vanilla JS re-implementing Bootstrap 3's `data-toggle` API. Only 16 of 156 templates use `x-data`.

| Dimension | Done | Why |
|---|---|---|
| Template markup | ~85% | Bootstrap tokens 477 → 88 (−82%); grid/form/button vocabulary fully gone |
| CSS | ~60% | 2,651 lines written, but 968 are the compat shim; 118 `.less` files still in tree |
| JavaScript | **~25%** | widget + SBE JS layer dropped and broken |
| Build / Flask glue | ~40% | self-labelled "quick and dirty"; prod path mismatch; no build hook |
| Old-pipeline cleanup | ~10% | nothing deleted; `AssetManager` is now dead code |
| Tests | **0%** | zero test files touched across 41 commits |

**Restoring the JS layer therefore comes before finishing templates.** Until the app works, no template change is verifiable, and while the shim absorbs the remainder, "done" is unmeasurable.

## Two constraints that gate everything

**1. `less_as_output = True` makes Bootstrap's removal a prerequisite for dropping Node.**
`web/assets/extension.py:90-94` sets `less_as_output = True`, so `LessImportFilter` rewrites every source into an `@import (less)` line and runs `lessc` **once** over the concatenation — Bootstrap 3, font-awesome, *and* the plain `.css` of select2 and DataTables. So `lessc` cannot go until Bootstrap 3's LESS is gone. Two side effects worth knowing: `Less.max_debug_level = None` means **lessc runs in DEBUG and in tests too**, and `filters.py:244` is a hard `assert` — a missing `lessc` is a 500 on first render, not a degradation. (The root `Dockerfile` installs neither Node nor Java, so a container built from it hits exactly that.)

**2. DataTables gates jQuery entirely.**
DataTables 1.9.4 backs every listing in the product — document folder and gallery, community members, social users, admin users and groups, document permissions, all generic `list_view` tables, the advanced-search builder, and XLS/CSV export. It pulls in `datatables-advanced-search.js` (**995 lines**), `datatables-setup.js` (a Bootstrap-3 pagination renderer), `sbe-datatable.js`, and `folder.js`'s 13-column config. Upgrading to DataTables 2 (still jQuery) is a materially different decision from replacing it. **That decision has to be made before any jQuery work, because it determines whether jQuery can ever leave.**

## Phase 2 — Make the branch work again

The largest and riskiest phase. Nothing downstream is verifiable until assets load.

**2.1 Fix the Vite↔Flask contract.** Drop the hand-rolled `vite_asset` in `src/abilian/setup/extensions.py` for `flask_vite`'s own tags — it is already initialised and then bypassed. Set `manifest: true` in `vite/vite.config.js`, reconcile `/static/vite/` vs `/static/abilian/sbe/vite/`, stop hardcoding `http://localhost:5173`, add a `make front` target wired into CI and packaging. Delete `vite/tailwind.config.js` — a v3-style config Tailwind v4 never loads, so its theme is silently inert — and the stale committed artifact `web/resources/css/vite-styles.css`.

**2.2 Ship built assets in the wheel.** `[tool.hatch.build.targets.wheel]` has no `artifacts`/`force-include` and `dist` is gitignored, so the wheel carries no CSS/JS. Ship the Vite output so `pip install abilian-sbe` yields a styled app with **zero Node, zero Java, zero build step** — strictly better than today, and it makes Hop3's job ordinary rather than special.

**2.3 Restore icons.** Import FontAwesome in `vite/src/styles.css`, or swap the 139 `fa fa-` usages (plus `action.py`'s `Glyphicon`/`FAIcon`) for inline SVG as `navbar.html` and `folder.html` already do.

**2.4 Restore the JS layer.** Covers `jquery.dataTables`, `select2`, the seven `js/widgets/*.js`, and the eight SBE scripts. **Re-add them as plain `<script>` tags first to get function back, then port to Vite entry points incrementally** — restoring behaviour and changing the module system at once is how this branch broke the first time. Replace the AMD shim in `abilian_base.html` only once real modules exist. Restore the dropped JS i18n bundles (select2 and datepicker locales).

**2.5 Fix the dead Alpine bits.** `x-collapse` is used in 6 templates without `@alpinejs/collapse` installed or registered. `ModalActionMixin` (`action.py:476`) dispatches an `open-modal` event nothing listens for, making all four modal action subclasses no-ops.

**Acceptance:** every page renders with icons and working widgets; documents module fully functional; a fresh clone plus documented build produces a styled app; smoke tests green.

**CHECKPOINT — the deployability gate.** This is where the branch stops being broken.

## Phase 4 — Delete the legacy pipeline

Ordering follows constraint 1: our LESS → Bootstrap's LESS → then and only then `lessc`.

1. **Port our own LESS** — 28 files, 2,312 lines (`web/resources/less/` 582, `sbe/static/less/` 1,730; `forum.less` alone is 771). The branch's `vite/src/components/*.css` is already a near 1:1 port by module name — **cherry-pick rather than redo**.
2. **Remove Bootstrap 3's LESS** (~70 vendored files) once Phase 3 has cleared the markup.
3. **Then drop lessc**: delete `Less`, `LessImportFilter`, `ImportCSSFilter` from `filters.py`; drop `less`/`lessc`/`htmlhint` from the root `package.json` (the migration never touched it); drop `cssmin`; drop `nodejs`/`npm` from `.builds/*.yml` and `yarn install` from the stale `.github/workflows/ci.yml`.
4. **Delete `src/abilian/web/assets/` entirely**, plus `flask-assets`/`webassets` from `pyproject.toml`, `asset_manager` from `extensions.py`, its two call sites, and the four `{% assets %}` blocks in `abilian_base.html`. `AssetManager` is already dead code — `extensions.py` swapped it for `Vite()`.
5. **Keep compatibility shims where deployments reach in.** `flask assets build` is invoked by name in four places — SlapOS `instance-sbe.cfg.in` (a *supervised service*, so a failing command becomes a restart loop, and `buildout.hash.cfg` md5-pins the file), `cloud/nua/nua-config.toml`, `pre_start.sh`, and the docs. Keep it as a no-op and keep `register_asset()` tolerated. Removing `{% assets %}` is all-or-nothing: a downstream override still containing one raises `TemplateSyntaxError` — a 500, not a degraded page.
6. **Rewrite our own jQuery glue** in vanilla JS — `sbe/static/js/*.js` and the ~262 inline `$(` call sites across 27 templates. Easiest first: `folder_edit.js` (41 lines, `$.ajax` → `fetch`), `document_viewer.js` (78 lines, pure DOM). `folder.js` and `folder_upload.js` stay coupled to DataTables/FileAPI and wait for the plugin decision. jQuery stays loaded for the vendored plugins.
7. **Write the plugin exit assessment** — per plugin: dependent feature, candidate replacement, effort. Recommended removal order once decided: bootbox → switch/timepicker/datepicker → typeahead+Hogan → tagsinput → FileAPI → select2 → DataTables → RequireJS. Note `abilian_init.js` is the hardest coupling point: it binds the server-side Babel locale to five plugins' global defaults.

**Acceptance:** no `.less` files; no webassets bundles; no Closure; all assets from Vite alone; `deptry src` clean.

- **Dependency surface** — commit the pinning work currently uncommitted on `devel`; prune deps orphaned by Phase 4; reduce `package.json` to what Vite needs. Note three tools drive one manifest today: `make install` runs `yarn`, CI runs `npm install`, `.github` runs `yarn install`, and both lockfiles exist untracked.
- **Docs** — rewrite `docs/installation.md` (it documents the pipeline we deleted, plus the nginx `/static/min/` rewrite) for Hop3; re-date `docs/roadmap.md` and tick UI Modernization; move **ADR 006 to *Accepted***, recording the two decisions actually made — the JS story and Hop3 as the deployment answer, which are precisely its two "Unresolved Questions". Fold `local-notes/` migration docs into `notes/` as the historical record.

## Decisions needed

1. **DataTables: upgrade to v2 (still jQuery) or replace?** Blocks all jQuery work. Note `vite/node_modules` already carries `datatables.net`, suggesting the branch assumed an upgrade.
2. **Alpine or the data-attribute shim** for interactivity — ADR 006 left this open, and the branch shipped both. Phase 3.2 forces the answer for modals; the same answer should apply everywhere.
3. **Ship built assets in the wheel?** Recommended in 2.2 — it makes deployment trivial for Hop3 and everyone else, at the cost of build output in the package.

## Risks

- **Phase 2 is the real project.** JS restoration is bigger than the remaining template work, and the branch's history shows what happens when behaviour and module system change together. Sequenced first, with its own gate.
- **Eight months stale, 41 commits, zero tests.** Phase 0 builds the net before anything moves.
- **Long-lived branch.** Phases 2–5 add weeks to a branch already well ahead. The Phase 3 checkpoint is an explicit early-landing option.
- **Downstream template overrides.** Deleting Bootstrap breaks any downstream project overriding templates with Bootstrap markup, and a stray `{% assets %}` becomes a 500. ADR 006's own "Lessons Learned" warns about exactly this.
